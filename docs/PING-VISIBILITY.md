# 首页延迟线路显示修复（1.2.21+ipstack.3）

> 历史记录。ipstack.4 起改为按线路协议归属判断，现行规则见 [THEME-OPTIMIZATION.md](THEME-OPTIMIZATION.md)。

用户报告：在卡片页将某 VPS 的 IPv6 设为隐藏，首页顶部 V6 标签消失，但该 VPS 的三个 V6 延迟/丢包仍在。ipstack.2 的实现仅控制标签，未满足用户要隐藏延迟线路的需求。

## 操作

- 主题设置 → 卡片 → 首页 V4 / V6 标签：明确隐藏某协议，现在也默认隐藏线路名带该协议标记的首页延迟。
- 主题设置 → 延迟 → 每台 VPS 的延迟线路显示：每台 VPS 的八个固定后端任务分别可选自动、显示、隐藏；可搜索 VPS，全部恢复自动。
- 单条「显示 / 隐藏」优先于协议默认规则。自动时，明确带 V4 / IPv4 或 V6 / IPv6 的名称才按对应协议规则判断；无标记或同时标记两种协议的线路维持显示。后端固定槽位 ID 不能可靠判断协议，不按槽位猜测。
- 「显示」只允许已经选入首页的任务显示，不会把未选入的任务添加到首页。先在原首页多线路设置选入所需线路。
- 隐藏时延迟和丢包一起移除，只影响首页，不停止探测，不删除历史，不改详情页图表。
- 大卡片、小卡片支持多线路；迷你和列表仍为原来的单线路，但同样遵守选中任务的隐藏规则。
- 管理员沿用自动同步，访客仅本机。已有标签和其他主题设置保留。

## 实现与限制

`homepagePingVisibilityOverrides` 按节点 UUID 和固定 task ID 保存布尔覆盖，名称修改不会令单条设置失效。自动模式的协议识别依赖显式线路名；名称改成其他协议时，自动显示规则跟随名称。没有协议标记时请使用单条设置。

新增本机稀疏修改键 `__luminaplusPingVisibilityEdits`，允许某条恢复自动，同时在保存前拉取后端新配置时保留其他节点、其他任务的更改；该本机键不进入后端、导出快照。后端整对象保存仍无原子并发保护，避免多设备同时保存。

过滤后保留原始 slot，供线路切换菜单使用，避免删除中间行后按钮换错任务。所有线路隐藏时不回退到默认单线路，也不增加空白占位。

没有新增外部网络地址、定时 HTTP 轮询、历史请求或依赖。原审查版依赖锁文件仅变更自定义包版本号；此前依赖审计结果仍为零条已知问题，未重新穷尽审查第三方包。
