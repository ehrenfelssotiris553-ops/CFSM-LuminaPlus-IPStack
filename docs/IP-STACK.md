# IPv4 / IPv6 独立显示定制版

版本：`1.2.21+ipstack.4`。基于 CF 版 LuminaPlus 1.2.21，不是 Komari 主题安装包。

本版将顶部标签与延迟显示完全分开，加入明确协议归属、每台 VPS 折叠设置、生效结果提示、配置冲突选择与未来时钟保护。升级会保留旧显示选择。详见 [主题优化说明](THEME-OPTIMIZATION.md)。此前同步修复见 [Bug 复查记录](BUG-REVIEW-2026-10-20.md)。

## 可以设置什么

进入首页右上角快捷栏 → **主题设置 → 卡片 → 首页 V4 / V6 标签**。

- 「默认显示 V4 标签」与「默认显示 V6 标签」分别控制处于自动模式的节点。
- 每台 VPS 各有 IPv4、IPv6 两个下拉框，互不影响。
- 可按名称、节点 ID、分组、地区搜索 VPS；可把全部节点恢复自动。
- 大卡片、小卡片、迷你、桌面列表均使用同一套规则。

| 单台选项 | 作用 |
| --- | --- |
| 自动 | 对应全局开关开启，并且后端上报对应标记时，才显示标签。 |
| 显示 | 为这台 VPS 固定显示该标签，可覆盖全局关闭和后端标记缺失。 |
| 隐藏 | 为这台 VPS 固定隐藏该标签，不影响另一种协议。 |

顶部「显示」是人工标签，不代表经过新的连通性检测，不显示真实 IP。标签与延迟独立，修改标签不会改变延迟线路。不会修改 VPS 网络、探针、采集或上报间隔。

例如：某台 VPS 选 IPv4「隐藏」、IPv6「显示」，首页只显示 V6；另一台可以单独保留 V4 或双栈。

登录管理员的修改沿用原主题自动保存到后端 `theme_options` 的机制；未登录访客的修改只留在自己的浏览器。刷新后仍保留。其他设备可能需要等后端配置缓存过期并刷新页面。

## 安装已构建的主题

本项目的 Cloudflare 主题加载器读取 **GitHub 目录地址**，不能把 ZIP 当作 Komari 主题直接上传安装。

1. 解压 `CFSM-LuminaPlus-1.2.21-ipstack.4-dist.zip`。其中根目录应是 `index.html` 与 `assets/`。
2. 在自己的 GitHub 账号下创建公开仓库，例如 `CFSM-LuminaPlus-IPStack`。
3. 把上一步的 `index.html`、`assets/` 发布在该仓库同一分支的根目录。不要多套一层 `dist/`，不要只上传 ZIP 文件。
4. 在 GitHub 查看这次**产物提交**的完整 40 位 SHA。
5. CF 监控后台 → 主题商店 → 自定义主题 URL，填入下面的格式，先预览，再应用：

   ```text
   https://github.com/你的用户名/CFSM-LuminaPlus-IPStack/tree/产物提交的40位SHA
   ```

这是一段格式示例，需要替换用户名和 SHA。若使用分支名也可以加载，但锁定 SHA 能固定你审查过的版本。不要填原作者的 URL，否则会安装没有本定制功能的原版。

你现有的 CF 后端和 VPS 探针不需要重新安装。测试时使用的是模拟数据，本包没有改动你的在线站点。

## 从 ipstack.3 更新

1. 解压 `CFSM-LuminaPlus-1.2.21-ipstack.4-update-from-ipstack.3.zip` 增量包。
2. 进入原仓库 `assets/`，上传包内 `assets/` 的 **11 个文件**并提交，保留旧文件。
3. 回仓库根目录，上传新版 `index.html` 覆盖同名文件并提交。先传资源再换入口。
4. 在 CF 后台将主题 URL 换成这次最终产物提交的 tree URL，先预览再应用。固定 SHA 的旧 URL 不会自动更新。
5. 首次以管理员身份打开新版会保存一次升级后的显示规则；访客不会写后端。已保存的旧 V4/V6 隐藏会转成独立的延迟组设置，之后互不影响。
6. 主题设置 → 延迟：确认“线路协议归属”，展开某台 VPS，调整组和单条线路。

如果不是从完整 ipstack.3 升级，请用完整 dist 包：根目录入口加 `assets/` 内 24 个文件。

## 从源码构建

使用源码包时，在解压后的项目目录运行：

```bash
npm ci --ignore-scripts
npm run lint
npm test
npm run build
```

使用支持本项目 Vite 的 Node.js（本次使用 24.19.0；上游工作流使用 Node.js 22）。`dist/` 中的文件就是要发布的主题产物。

源码包保留了上游 `.github/workflows/build-theme.yml`：在你自己的源码仓库 `main` 提交后，它会构建并发布到该仓库的 `dist` 分支。该工作流只使用 GitHub 自带的仓库令牌，不需要填写 Cloudflare API Token 或 VPS 密码。若仅上传已构建产物到专用仓库，无需启用 Actions。

## 配置格式

下例的 `节点ID` 是 API 返回的 ID，不是 VPS 名称，也不一定是 IP。可以完全通过界面操作，无需手写 JSON。

```json
{
  "showIpv4": true,
  "showIpv6": true,
  "homepageIpStackOverrides": {
    "节点ID-A": { "ipv4": false, "ipv6": true },
    "节点ID-B": { "ipv6": false }
  }
}
```

省略某个协议表示自动；`true` 固定显示；`false` 固定隐藏。省略整个新配置时，默认继续按原版的后端标记显示。无须修改后端数据库结构。

## 更新与回退

- 保留本包源码和安装时的产物 SHA。直接换回原作者版本会失去新增设置的界面和效果。
- 页脚的 GitHub 检查只提示上游版本，不会自动下载并替换本主题。后续合并上游代码时需保留本次修改。
- 回退主题可在后台切回原主题或原 URL。新配置字段只影响本定制版，不会更改服务器网络或删除历史数据。
