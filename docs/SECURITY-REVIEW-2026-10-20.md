## 结论

本次重点静态审查、依赖扫描、重建比对与浏览器验证中，**没有发现后门、挖矿、隐藏远程命令执行或向陌生服务发送管理员登录密钥的逻辑**。

原锁文件有 10 个受影响依赖包（7 高、3 中，按 npm audit 的包级归类，含间接依赖），存在已知安全公告。并非这些公告都能在本静态主题中利用，也不能把它们直接等同于后门。定制版在现有兼容版本范围内更新了锁文件；复扫为 **0 个已知漏洞**。

这不是完整形式化审计或绝对无漏洞保证。没有逐个完整审计所有第三方依赖的源代码，也没有对用户真实站点做侵入测试。

## 检查内容与发现

- 查看入口、API/鉴权封装、WebSocket、主题配置自动同步、外链、DOM 注入方式、构建脚本、GitHub Actions 和依赖锁文件。
- 检索并跟踪动态代码执行、危险 HTML 注入、外部脚本、后台计算/挖矿、可疑混淆、系统进程调用与秘密外传入口；未发现相应恶意实现。
- 普通站点数据按 React 文本/属性渲染；没有发现把服务器名称、标签或主题设置直接当 HTML 执行的入口。
- 版本检查下载的 GitHub HTML 只用来提取版本 meta，不作为脚本或页面执行。
- 生产构建不包含开发 mock 的定时快照轮询；修改功能复用了现有节点列表，不新增每台 VPS 的网络查询。
- `package-lock.json` 中下载地址均来自 `registry.npmjs.org`，记录完整性值。原锁文件仅标记可选的 macOS `fsevents` 安装脚本；本次安装禁用生命周期脚本，不影响构建。
- 上游 Actions 的主要行为是安装依赖、检查、构建、把产物提交到自己仓库的 dist 分支，以及创建 Release。使用自带 `GITHUB_TOKEN` 的仓库写权限与此用途相符，没有要求 CF 管理令牌或 VPS 密码。第三方 Action 采用版本标签而非固定 SHA，仍有通常的供应链信任要求。

## 外部请求与凭证

| 目的地 | 作用及凭证情况 |
| --- | --- |
| 同源 `/api/*` 与 `/api/ws` | 监控数据、配置和实时更新。登录后按 CF 后端约定使用 JWT/Cookie。管理员配置写入入口是 `/api/theme_options`。 |
| `api.frankfurter.dev` 或管理员自设汇率 URL | 取得汇率，不发送 VPS 数据或登录密钥。服务端会看见浏览器访问 IP；本定制版明确禁止带 Cookie 和 Referer。 |
| `raw.githubusercontent.com/volcano-1025/.../dist/index.html` | 登录站长的上游版本提示，成功缓存约 12 小时。没有登录密钥；本定制版明确禁止带 Cookie 和 Referer。 |
| `challenges.cloudflare.com` | 站点启用全局 Turnstile 时加载官方验证脚本。未见额外非官方脚本服务。 |
| 自定义背景图、head、script | 由你现有 CF 后端的外观设置注入，需要自行信任所填内容；不属于本次新增功能。 |

原主题也支持在静态托管模式中通过 `apiBase` 指定外部后端，并向这些后端发送登录凭证。不要把不受信任的服务放进该列表。跨域 WSS 为兼容后端会把 JWT 放进查询参数，可能进入接收方访问日志。你使用 **CF 后端同源托管主题** 时，无须填写额外后端，WSS 也不必把 JWT 放进 URL。

主题脚本运行在监控站点的同一来源，理论上有能力访问该来源的浏览器登录存储及 API。因此安全结论不能写成「只是主题，所以不可能窃取登录信息」。本次检查没有发现该类窃取行为；以后仍应锁定可信发布提交。
