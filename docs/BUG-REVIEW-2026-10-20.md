# 独立 IPv4 / IPv6 设置 Bug 复查记录

复查对象：`1.2.21+ipstack.1`，源码提交 `cc915e92d7ddb07f515014516cb4fb079768f52e`。

修复版本：`1.2.21+ipstack.2`。本次没有改动用户在线 CF 站点，也没有操作 VPS。

## 已复现并修复的问题

| 问题 | 触发方式与影响 | 修复 |
| --- | --- | --- |
| 旧配置整表覆盖 | 手机改节点 A 的 V4，另一设备已改 A 的 V6 或节点 B；保存旧表时可能把后者清掉。 | 本机只记录真正改过的节点和协议，同步时合并到刚取得的后端配置。恢复自动也作为明确操作保留。 |
| 表单回流覆盖 | 设置页尚有未保存编辑，此时读到另一设备的新配置；旧草稿整项保留会挡住没编辑过的节点/协议更新。 | 旧草稿与新配置按节点、协议合并，保留正在编辑的部分。 |
| 缓存保护忽略更新 | 本机刚保存后的 150 秒保护期内，收到另一设备更高 `luminaplusSyncedAt` 的配置，原实现仍一直采用自己的旧快照。 | 识别更新同步标记，采用并暂存新快照，继续拒绝随后返回的旧缓存。 |
| 清空本地存储后其他页不刷新 | 一个标签页执行清空本地存储，其他已打开页面的内存缓存没有失效。 | 响应 `storage` 事件的空 key，重新读取本机设置。 |

上表四种触发均先加入回归测试，在修改前确认失败，再修复至通过。前两项属于同一类逐节点配置合并问题。

- 56 个测试文件，**629 项测试通过**；新增 8 个回归用例。
- ESLint、TypeScript、正式 Vite 构建通过。
- 正式构建产物使用 7 台模拟 VPS 做浏览器检查，覆盖大、小、迷你、列表及 390px 手机页面。
- 验证管理员后端保存、访客本机保存、刷新保留、逐协议恢复自动、全部恢复自动。
- 验证连续修改、保存尚未返回时撤销为自动；只在本机使用的改动标记不会发送到后端。
- 验证改完立刻离开设置页仍保存；另一标签页清空设置后原页面更新。
- 验证旧表单与后台新快照交错时保留另一节点/协议的更新，以及缓存保护期内的更新识别。
- 首页推进 125 秒，没有新增 HTTP 定时轮询或历史查询。

浏览器结果见 `../audit/2026-10-20/browser-checks.json`。本次依赖版本未改变，原依赖安全扫描证据继续适用。

## 范围与使用限制

这些验证使用正式 JS/CSS 与模拟 API，不等于已经验证用户真实 CF 域名的 CSP、缓存和登录环境。安装前可先用监控后台的预览。

本次修复能保留读取到的新快照里未编辑的字段，但后端 `/api/theme_options` 仍是整份写入，没有版本条件更新；如果两台设备真正同时写入，或读到的都是旧 CF 缓存，前端不能提供数据库级并发保证。同步标记也沿用原项目的客户端时间，设备时钟应正常。此限制没有通过新增轮询或改后端来规避。

新版本兼容已经存入后端的 `homepageIpStackOverrides`，不需要重装探针。`ipstack.1` 浏览器中尚未同步的旧整表覆盖保留原含义，无法从旧存储推断当时究竟只编辑了哪些字段；这类旧待同步配置可先核对或使用「改用后端配置」清除。
